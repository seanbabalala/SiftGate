# 客户生命周期正式发行 Goal

状态：2026-10-08，用户已批准完成四个模块，并在完整验收后发布新版本。Goal处于执行中；此文档不是宣称功能已完成。

## 最终交付

1. **Release Center**：当前/目标版本和差异、可信发行身份、明确兼容范围、预检有效期、维护窗口、不可变计划与真实阶段记录。
2. **Recovery Vault**：备份清单、完整性与恢复演练分开、隔离恢复及业务数据核对证据、保留原实例与新写入的恢复路径。
3. **Control Room**：独立于网关的运维Web/CLI、持久任务、关闭页面不丢任务、网关停止时仍能观察进度；网关没有Docker权限。
4. **Fleet Console**：独立运维身份及角色、提议/批准分离、显式纳管、多实例批次、试点与扩大范围、暂停/失败门槛、经过验证的离线升级。
5. **正式发行**：完整测试与真实跨版本演练、PR/主分支CI、原生双架构镜像、可验证发行元数据和客户工具、公开Release及匿名可安装性验证。

## 授权与不变量

- 用户本轮授权实现、提交、推送以及验收通过后的正式发版；不得跳过已有CI、不可变tag、公开附件核对等门禁。
- **发布不等于部署。现网2099的重启、重建、迁移、换镜像、加入Fleet或开启自动升级仍须单独确认。**
- 在已使用的隔离worktree继续，不覆盖Desktop主检出或既有未提交成果。不把旧P0/P1-A证据冒充本轮全量结果。
- 使用Rancher Desktop Moby的显式socket；不改变Docker全局context或系统启动项。
- 使用新目录、新端口、合成凭据、mock upstream；不读取生产请求正文，不调用真实付费模型。
- 官方Logo只复用现有favicon.svg；七语言、窄屏、键盘和语义化状态按真实界面验收。
- 不伪造在线心跳、成功任务、签名校验或恢复演练。不把同代码镜像替换称为跨版本升级。
- 默认仅检查更新。任何部署必须绑定确切发行、安装身份、源状态、批准身份和维护窗口；中心断联不影响网关数据面。
- SQLite实例禁止双容器共用一个活动文件冒充零停机；PostgreSQL必须单独的原生备份/恢复证据，没有能力时明确阻止而非假装支持。

## 技术边界

- 现有P1-A只读桥继续保留。高权限Web控制面是**独立宿主进程和独立认证**，不是给网关补一个通用exec端点。
- 可信发行优先复用GitHub Actions OIDC/Sigstore证明，绑定仓库、受信工作流、tag、源commit与具体artifact摘要；客户验证用明确版本的官方验证器，而非自行实现密码学。
- 离线包不能自带一份任意根证书就获得信任：验证器/信任根必须独立引入，或来自之前可信的在线初始化。归档先验证再解压/加载。
- 兼容性由经测试且被签名的发行契约明确声明；不对任意旧版本、未来schema或任意第三方镜像承诺安全升级。
- 纳管仅作用于显式登记的安装；UI输入不能指定任意主机路径或shell命令。多主机通道必须认证并固定远端身份。
- 批次批准必须由不同于提议者的具名身份完成。共享Dashboard管理员不冒充企业多人审计。紧急主机操作单独标记。
- 工具、Compose、镜像和数据库组合必须成组核对。工具包版本化存放；失败保留现场，不盲目重放，也不自动用旧快照覆盖新写入。
