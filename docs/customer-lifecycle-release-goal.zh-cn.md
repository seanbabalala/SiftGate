# 客户生命周期：发行验收标准

本文是公开验收标准，不是维护者本机的部署台账或执行授权。
当前版本范围见[工程基线](BASELINE.md)，可安装性以确切版本的发布流水线、
签名附件和原生双架构冷安装结果为准。

## 四个模块

| 模块 | 必须具备的能力 |
|---|---|
| Release Center | 版本差异、可信发行身份、兼容性预检、维护窗口和真实进度 |
| Recovery Vault | 备份校验与恢复演练分开；隔离恢复、数据核对及安全恢复路径 |
| Control Room | 独立身份、持久任务；页面关闭及网关重启时任务不丢失 |
| Fleet Console | 明确纳管、权限分离、双人审批、试点与逐批推进、暂停及离线升级 |

## 发行门禁

- 确切 main 提交完整 CI 成功，不能复用其他提交的绿灯。
- 原生 Linux AMD64/ARM64 构建与全新安装、支持来源的真实升级、恢复及批次治理验收。
- 版本、源提交、镜像 digest、宿主工具和兼容性绑定到签名发行清单。
- 四件套字节/签名核对后公开，另由干净环境匿名拉取镜像并完成冷安装。
- 扫描发布输入和历史凭证；公开资料不得夹带真实配置、客户正文或内部部署记录。

## 安全边界

发布不等于部署。没有安装所有者的明确批准，不拉取替换其运行容器，
不自动加入 Fleet，不更改调用 Key，不重启服务。SQLite 不用双写伪装零停机；
PostgreSQL 采用数据库原生备份恢复流程。失败须保留证据并进入人工核对，
不能伪造成功、跳过签名验证或盲目重放操作。

测试中的合成发行输入不等于真实发布者验签。共享物理宿主的独立 SSH
端点测试不等于硬件故障切换证明。测试限制必须与结果一同披露。
