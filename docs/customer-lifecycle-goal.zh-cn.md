让客户从安装、认领、接入到维护与恢复都有清楚、可验证的下一步。保持已有调用地址、
供应商凭据、API Key 和计价数据；不把“漂亮页面”替代权限、持久状态和恢复演练。

- 品牌标识只复用现有 `frontend/public/favicon.svg`（与侧栏一致），不重绘、不以通用盾牌替代；布局与交互优化不包含品牌改版。

- 现网 `siftgate-2099` 不因开发、测试或发布而重启、重建、换镜像或改变启动策略。
- 只在隔离工作区及合成测试目录工作；新端口、新配置、新数据库、mock upstream。
- 不复制生产密钥、不发送真实付费模型请求、不读取生产请求正文。
- 提交、推送、正式镜像发布、升级现网是不同动作；本轮不隐含后三者授权。
- 本机使用 Rancher Desktop Moby，测试显式选择它的 socket，不切全局 Docker context。

## P0-A 行为契约

### 新安装

安装器显式创建 `dashboard.identity_file`。首次访问验证单次、15分钟有效、绑定本地
身份的激活码，设置管理员密码，再登录。不能让第一个访问页面的人直接认领。
激活码明文只保存在权限 0600 的本机文件，HTTP 状态只返回必要的模式与过期状态。

### 旧安装

旧 password/OIDC 配置原样使用，不因为数据库空、用户缺失或密码缺失开放激活。
显式身份文件缺失/损坏必须拒绝访问。直接源码启动却未配置凭据时拒绝启动，取消
“生成长期随机密码并写日志”的后备流程。这是有意的兼容性变化，必须进入发行说明。

### 凭据变更

已登录改密需验证当前密码。遗失密码只能由有主机权限的安装账户签发恢复码；无邮件
配置时不伪造邮件找回。消费激活/恢复码或改密时原子更新身份并轮换管理会话签名密钥。
旧会话不得继续调用受保护端点；Gateway API Key、供应商凭据和业务数据不改变。
新身份模式目前不支持邀请、OIDC混用或多节点共享身份文件。

### 备份与恢复

继续使用既有 SQLite 备份与明确排空/停机策略。备份排除明文访问码、临时身份文件
和锁；副本清除待消费码、变更签名密钥。每次恢复至新目录再次轮换密钥，不复活原实例
或另一份恢复实例的管理会话。恢复后使用备份时的管理员密码重新登录。
身份恢复与数据库恢复不同：`access-code` 不重启，完整 `backup/restore/upgrade` 不是零停机。

## P0-A 验收矩阵

- 并发认领仅成功一次；错误码、过期码、重放码、跨实例码、时钟倒退均拒绝。
- 密码长度按 Unicode 字符和 UTF-8 字节检查，不发生 bcrypt 截断。
- 未认领不能进入后台；状态/错误不返回码、密码、哈希、私有路径或会话密钥。
- 身份文件权限/链接/损坏/缺失、排他锁、写失败均保持拒绝访问。
- 恢复码重签失效旧码；改密/恢复撤销 JWT；再次打开实例不会重置管理员。
- 旧密码、OIDC、Cookie、被允许的 Bearer 登录继续工作；本地 token 存在不再等于认证成功。
- 浏览器跨站/同站不同源变更拒绝，限流与登录共享；接口错误码本地化。
- 合成 Docker 安装→激活→登录→写配置→mock 调用→备份→独立恢复链路通过。
- 管理恢复前后测试容器 ID/启动时间不变；恢复副本重新登录、Key与日志保留。
- 前后端构建、七语言检查、后端测试、安装器测试、桌面/窄屏人工可视验收均记录真实结果。
- 最终再次核对现网容器身份、启动时间与重启次数，不能用一句“没动”替代检查。
