> **先完成所有开发与隔离验收，交付结果，再等待用户单独明确批准维护窗口。没有这个批准，不得部署、重启或间接触发重启。**

### SAFE-01：完成前禁止触碰的生产对象

以下约束适用于主执行者、辅助脚本、测试命令、构建钩子及将来获准使用的协作执行者：

- 不停止、重启、杀死、暂停、调试附加或替换正在运行的 2099 进程。
- 不对生产 launchd/systemd 服务执行 restart、kickstart、bootout、bootstrap、reload；不操作承载该服务的容器。
- 不修改生产启动脚本、plist、服务环境变量、`current` 符号链接、活动发布目录及其前端静态资源。
- 不修改或热加载生产 `gateway.config.yaml`、价格覆盖文件、密钥、费率或预算策略。
- 不修改生产看门狗、其维护标记、通知导出文件、状态文件或重启阈值；不得利用看门狗代为重启。
- 不在生产 SQLite/PostgreSQL 上执行迁移、写入、清理、回填、压缩、检查点或恢复备份。
- 不通过后台 UI/API 发布价格、创建测试节点、修改模型配置、配置真实告警或执行其他生产写操作。
- 不对 2099 做故障注入、压测、真实付费模型请求或长时间数据库扫描。
- 不在与生产共享的依赖目录中执行安装、原生依赖重编译或清理；不要把隔离目录软链接到生产可写资源。
- 不修改本任务自身使用的模型路由或上游环境；不要让验证请求经过生产 Gateway。

允许的生产读取仅限开始/结束的低频轻量检查：进程身份、发布清单、配置摘要校验和、已有健康接口。不要输出配置内容或凭证。数据库内容不是完成本 Goal 的前提。

### SAFE-02：隔离环境的必要条件

1. 使用独立 Git worktree，包含当前已部署修复，不能从较旧 main 开始后误覆盖可靠性与告警能力。
2. 使用独立依赖、独立构建产物、独立临时目录及可销毁数据库。需要模拟生产数据结构时生成脱敏合成数据。
3. 测试服务绑定 `127.0.0.1` 的系统分配端口；不得绑定、占用或代理 2099。
4. 外部厂商请求默认 mock，测试 webhook 默认本地接收器；不使用生产 provider key。
5. 启动测试前清除或覆盖生产配置路径、数据库连接串、看门狗导出路径、遥测目标、日志接收目标和插件目录。
6. 审查构建脚本、测试发现路径、npm 生命周期钩子、Docker volume 与环境变量后才能运行；命令名字为 test 不代表安全。

8. 临时资源清理只能按当前任务创建的明确目录、PID、容器标签执行，禁止宽泛进程匹配或通配删除。

## 1. Goal 与成功标准

### G-01：一句话目标

把 Gateway 从“以输入/输出 token 单价为核心的成本估算”升级为一套**统一用量模型、确定性价格规则、可追溯费用明细、完整后台配置与安全版本发布**组成的计价系统。

### G-02：必须满足的用户结果

1. 管理员可配置基础 token、缓存读写、长上下文、服务等级、峰谷、图片、音频、视频计费规则，不再手改 YAML 才能完成日常调价。
2. 路由估算、预算预留、实际结算、调用日志、内部费用报表与前端试算使用同一个计价核心。
3. 每笔新请求可以解释“为什么按这个价格计算”，包括选中的节点、模型、用量、规则、价格版本、汇率、数量与最终金额。
4. 发布新价只影响新请求；在途请求、已受理的异步任务和历史记录不因调价而变价。
5. 未定价、缺少用量、明确免费、估算与已结算不能混为零费用。
6. 旧配置、旧预算口径、API 协议、现有数据库启动方式与可靠性功能保持兼容。
7. 企业可以在后台自行管理，支持现有七种语言，并有权限、审计、冲突检查及预览。
8. 达成以上结果期间，遵守第 0 节生产保护要求。

### G-03：完成度定义

仅增加 schema 字段、做出表单、显示参考价格或得到一张截图，均不算完成。

只有“配置 → 解析 → 采集用量 → 估算/预留 → 最终计算 → 持久化 → 报表/明细 → 回放测试”闭环通过，才可标记对应能力完成。

## 2. 已核实的现状与需要保留的能力

本节描述上述提交基线，不等同于未来运行环境，也不构成对厂商当前价格的声明。

| --- | --- | --- |
| 价格结构 | 已有基础 token、缓存及部分媒体价格字段 | 统一单位、条件规则、版本和真正执行路径 |

## 3. 范围与非目标

### SCOPE-01：最终开发交付必须覆盖

- 统一计量维度、用量来源和缺失状态。
- 基础 token、缓存读、普通缓存写、5 分钟/1 小时缓存写。
- 总输入量阶梯：整单阶梯为首批必需；超额分段需要明确模式和独立验证，不得混用。
- 标准、Priority/Fast、Flex、Batch 的价格变体框架；仅对已验证实际支持的模型启用。
- 周期峰谷时间窗、时区、指定日期与节假日覆盖、有效期。
- 图片数量、请求次数、音频时长/字符/分类型 token、视频时长/次数及媒体规格条件。
- 同时含基础调用费和用量费的组合计费，防止重复计量。
- 原币与报告币、汇率快照、确定性精度和取整。
- 不可变价格版本、按请求/任务固定价格、明细持久化、历史回放。
- 预算预留/结算接入、失败/取消的成本状态、异步视频幂等结算。
- 后台配置、复制、导入导出、校验、试算、草稿发布、回滚与审计。
- 数据兼容迁移脚本及隔离演练，不执行生产迁移。
- Linux/Docker 和 SQLite/PostgreSQL 支持边界的验证证据。

### SCOPE-02：本 Goal 不做

- 充值、支付、代收、消费者账单、销售加价、渠道分销或中转站余额体系。
- 自动将官方参考价视为供应商合同价，自动接受所有价格同步变化。
- 静默回写、重算或删除历史生产账单/日志。
- 自动修改正在使用的供应商、模型映射、路由、预算阈值、熔断、日志保留或通知目的地。
- 中心远程自动升级、多机高可用、全网供应商抓取、完整税务/财务系统。
- 无限制的可编程计价脚本、用户提供的 JavaScript/SQL 表达式。
- 为计价而存储提示词、模型输出、工具内容、音视频原始文件或未脱敏 provider 响应。
- 把“所有厂商的全部定价方式”作为不可验证的承诺；未支持的规则必须显式标记。

工具调用费、存储容量×时间、像素/分块计费等保留扩展点。除已有支持路径需要外，本 Goal 不要求为每个厂商实现全量解析器；未来扩展不得改变已有维度含义。

## 4. 术语与成本口径

| 术语 | 规范定义 |
| --- | --- |
| 原始用量证据 | 从请求元数据、响应 usage、任务结果提取的允许列表字段；不保存原始内容 |
| 规范化用量 | 明确单位、包含关系、来源和状态的计量数量 |
| 价格簿 `PriceBook` | 一组面向模型/节点的规则、费率与来源信息 |
| 价格版本 | 发布后不可变的完整价格簿内容及哈希 |
| 单价组件 `RateComponent` | 一个维度的货币金额、基准数量、计量单位和取整策略 |
| 规则变体 `PricingRule` | 在指定上下文、时段、服务等级、媒体规格下选择的价格组件组合 |
| 估算 `estimate` | 请求前根据已知或推算用量计算，必须标注不确定性 |
| 预留 `reservation` | 为预算准入预占额度，不等于实际成本 |
| 计价完成 `priced` | 已知用量按已固定规则计算完成，不代表供应商已出正式发票 |
| 供应商核对 `reconciled` | 另有供应商账单/权威证据完成核对；不得由本地计算自动推定 |
| 上游成本 | 本次或本次尝试实际产生的供应商费用，可能仍为估算或未知 |
| 内部分摊 | 企业选择的内部使用计费口径，默认跟随成本，也可显式保留旧逻辑预算语义 |
| 节省金额 | 在明确参考方案下计算的反事实差额，不能直接记作实际支出 |

UI 禁止把 `priced` 直接显示为“供应商账单已确认”。实际确认程度由独立的 `evidence_status` 表示。

## 5. 计量契约

### METER-01：统一维度

| 维度族 | 必需维度或细分 | 约束 |
| --- | --- | --- |
| 输入 token | 总输入、未缓存输入 | 总输入用于阈值判断，未缓存输入用于普通输入价格；不能同时双重计费 |
| 缓存读取 | 缓存读取 token | 是总输入的子集；供应商特殊包含关系由适配器规范化 |
| 缓存写入 | 普通写入、5m 写入、1h 写入 | 已知 TTL 子项与汇总写入互斥计费；未知 TTL 不能猜成 5m |
| 输出 token | 输出合计、可选文本/音频/图像/推理子项 | 供应商已包含在输出合计的 reasoning 不重复收费 |
| 多模态输入 | 文本、音频、图像 token 子项 | 只有确实提供不同单价且有细分证据时按子项计算 |
| 请求次数 | `request_count` | 一个客户请求和多个上游尝试需分开记录 |
| 图片 | `image_count` | 实际成功生成数优先；请求 `n` 只作为预估或显式合同口径 |
| 音频 | `audio_input_seconds`、`audio_output_seconds`、`text_characters` | 声音时长不是请求延迟；字符不是 UTF-8 字节数 |
| 视频 | `video_seconds`、`video_generation_count` | 实际/请求时长来源必须标记；重试、轮询、下载不自动新增生成数量 |
| Rerank | `rerank_request_count`、`rerank_document_count` | 每 1000 次与每 1000 篇是不同计价维度 |
| Realtime | `session_seconds` 及实际报告的音频/文本 token | 会话费用与模型费用只有显式配置时相加 |

现有 embeddings 按输入 token 计量，允许独立单价，不与聊天输出字段硬绑定。

### METER-02：每个数量的必要属性

- `dimension`、`unit`、整数基数与缩放比例；金额和大整数对外使用字符串。
- `source`：`provider_usage`、`provider_job_result`、`request_metadata`、`local_measurement`、`heuristic`。
- `quality`：`observed`、`estimated`、`missing`、`unsupported`。
- `includes` / `subset_of` 的标准化关系，防止缓存、reasoning、图片 token 被重复计算。
- `adapter_id` / `adapter_version`，记录本次规范化使用的解析版本。
- 缺失不等于 0；只有可靠证据或明确定义的本地无上游调用才产生确认的 0。

### METER-03：解析与流式行为

1. 尽量在已有 usage schema/适配器上扩展，不为每个入口单独再造规则。
2. 原生与转换后的 Chat Completions、Responses、Messages、Gemini 路径要得到等价规范用量。
3. 区分 SSE 累计用量和增量用量；不得把多次累计报告相加。
4. 最终 usage 覆盖估算时保留证据来源，不覆盖已完成结算而导致重复累计。
5. 客户取消后若仍能得到供应商用量，记录上游已发生费用；无法得到时标记未知/估算，不武断记零。
6. 对负数、非有限数、格式错误、超安全整数、缓存子项超总量进行验证并输出结构化诊断。
7. 允许降级为受标记的估算以兼容业务，但不得因为普通计价解析失败使本来有效的模型响应变成 5xx。

## 6. 价格数据模型与确定性计算

### PRICE-01：核心对象契约

| 对象 | 至少包含 |
| --- | --- |
| `PriceBook` | 稳定 ID、名称、管理作用域、模型/节点匹配、来源、负责人、状态 |
| `PriceBookVersion` | 版本 ID、schema 版本、不可变内容哈希、父版本/来源版本、创建与发布时间、有效区间、来源链接、币种 |
| `PricingCatalogSnapshot` | 请求准入时固定的目录修订号、模型/节点绑定及价格/日历/FX 版本引用；覆盖后续候选和 fallback，不复制所有价格正文 |
| `RateComponent` | 维度、货币、金额字符串、每多少单位、数量取整、金额取整、明确免费标志 |
| `PricingRule` | 稳定 ID、名称、条件、优先级、互斥组、组件、明确引用的继承/修正关系 |
| `PricingContext` | 请求/尝试/任务 ID、节点、请求模型、实际模型、请求与实际服务等级、时间、媒体规格、报告币 |
| `PriceSelection` | 所有命中与淘汰原因、选中版本/规则、时间依据、日历版本、FX 版本 |
| `CostComputation` | 状态、按维度用量、原币金额、报告币金额、明细、缺失项、估算原因、计算器版本 |
| `CostLine` | 用量、原始/计费数量、单价、单位基数、倍率、原币/报告币小计、引用规则 |
| `Settlement` | 幂等键、预留引用、状态、最终费用快照、尝试合计、冲正或修订关系 |

类名和物理表名可以在 M0 设计阶段微调，语义和必需字段不能减少。不得把可执行规则仅藏在无人校验的任意 JSON 中。

### PRICE-02：金额和数量精度

- 核心计算禁止使用 JavaScript 浮点金额直接累计。
- 金额使用带币种的整数定点或精确十进制；精度至少支持百万分之一货币单位。
- 数量×费率/单位基数用整数分子分母或精确十进制计算，保留中间余数，不能每行过早截断导致大量微额免费。
- 时长至少保留毫秒级原始精度，单独应用按秒/分钟向上取整、最小计费单位等合同规则。
- 默认只在约定结算边界统一金额舍入；需支持明确的 `half_even` 与供应商合同要求的替代策略。
- 展示行的舍入差与总额必须通过明确调整项或余数分配解释，确保明细可加总。
- 输入单价为十进制字符串；不要在前端用 `parseFloat` 转换后再声称精确。
- 旧 `cost_usd` 仅作为兼容投影，不继续充当新账务的唯一权威数值。

### PRICE-03：币种与汇率

- 保留供应商原币，例如 USD、CNY；所有报表金额必须有币种标签。
- 报告币汇总需要固定的汇率版本、来源、比例和生效时间；每次请求/任务固定该版本。
- 汇率由显式录入或获准的同步来源提供，不在请求热路径进行外部汇率请求。
- 缺少汇率时保留原币金额，报告币金额为未知；不得把 CNY 数字标成 USD 或当成 0。
- 异币种不得直接相加。多次尝试的原币费用可分币种保存，统一报告币需有有效 FX 证据。
- 上游价格变更和汇率变更分别审计；历史记录使用历史快照。

### PRICE-04：继承与来源优先级

默认顺序为：显式节点模型绑定 → 网关模型绑定 → 已批准的目录版本 → 已标记的旧配置兼容快照。

未批准的抓取/同步价只作为参考，不自动参与生产计价。参考价可以导入草稿，由管理员确认后发布。

继承规则必须显式引用不可变父版本，发布时展开为完整的有效组件清单。缺失某一组件时：

- 若显式允许从父版本继承，显示继承来源。
- 若存在用量但没有可用费率，返回 `partial` / `unpriced`。
- 不根据模型名称擅自补全缓存倍率、Priority 倍率或上下文倍率。
- 没有费用发生的维度不要求费率，避免纯图片价被强迫填写虚假 token 输入/输出价。

### PRICE-05：缓存与模型特定规则

- 厂商/模型的缓存读取比例和写入期限单价均可显式配置。
- 旧的自动倍率推断如需保留，只能进入 `legacy_estimate` 路径并明确标记，不能伪装成已核验价格。
- 缓存写入汇总存在但 TTL 子项缺失时，使用明确配置的“未知 TTL”估算策略，或返回缺失状态。
- 同一 token 不同时收普通输入价与缓存读取/写入价；不把缓存 TTL 存储费与写入费混为一项。

## 7. 条件规则与匹配优先级

### RULE-01：匹配顺序

1. 在请求准入时固定计价目录快照；每次尝试按实际执行节点、实际模型、调用类型，在该快照内选择价格版本。后续 fallback 不重新读取当前活动版本。
2. 根据权威响应或任务结果解析实际服务等级；响应没有证据时保留请求等级并标记依据。
3. 按该规则指定的时间依据，选择时间窗与日历版本。
4. 按规范化总输入量判断上下文阶梯。
5. 按已声明的媒体规格条件选择价格变体。
6. 展开明确组件及允许的修正，验证维度不重叠，再计算金额。

“第一个匹配就算了”不是冲突解决规则。相同优先级、相同互斥组存在可能同时命中的不同规则时，发布必须失败。

### RULE-02：组合语义

- 普通阶梯、长上下文阶梯同属互斥组，一次只选择一个。
- 峰时、谷时同属互斥组，一次只选择一个。
- Priority 不自动在所有价上乘 2；可以配置绝对价或明确的维度倍率。
- 按次基本费与按秒费用只有 `additive` 关系被明确声明时才能叠加。
- 绝对价覆盖和倍率修正必须指定顺序，禁止根据对象键顺序或数组遍历偶然确定。
- M0 必须冻结匹配器的支持条件集合；未知条件类型导致草稿校验失败，不能忽略。

### RULE-03：长上下文阶梯

- 默认阶梯判断依据为规范化 `total_input_tokens`，包含已规范化的缓存子项；不是只看未缓存输入。
- 阈值使用明确整数边界，内部使用 `[min, max)`；UI 可显示“输入 > 272,000”等人类可读形式。
- `whole_request`：按整单输入所在档位，为各个用量维度选择价格。输入和输出倍率可不同。
- `graduated`：仅对明确的数量区间分段计算；不能自动扩展成“输出也按输入分段”。
- 第一批必须完整支持 `whole_request`。若 `graduated` 未交付，UI/API 必须禁用该模式并返回 `unsupported_rule_mode`，不得假装等价。
- 上游重试/fallback 每次尝试按该次总输入及固定价格计算；不能用请求重试次数放大 token 后再错误触发长上下文阶梯。
- 边界 `272000` / `272001` 仅作为合成测试值与常见模式示例，不是所有 GPT 模型的通用政策。

### RULE-04：峰谷与日历

- 配置字段：IANA 时区、星期集合、每日多个 `[start, end)` 时间窗、有效起止日期、节假日日历及指定日期覆盖。
- 覆盖优先顺序：显式指定日期 → 版本化节假日例外 → 星期时间窗 → 已配置兜底。
- 中国法定节假日与调休工作日是不同语义；是否将调休周末视作高峰必须由具体合同规则指定，不从操作系统工作日推断。
- 支持跨午夜时间窗，发布时归一化并显示覆盖后的周视图。
- 时区转换从绝对时间戳开始，不能使用浏览器/服务器的隐含本地时区。测试夏令时跳变和重复小时。
- 日历必须有版本与覆盖年限。覆盖失效时警告并采用明确的未知/保守估算策略，不能静默降为谷价。
- 计价时间依据默认 `attempt_dispatched_at`。只有厂商约定并验证后，才能选择 `provider_accepted_at` 或 `completed_at`。
- 即使按完成时间选择窗口，也在开始时固定价格簿/日历版本；完成时只在这个版本内按时间选规则。
- 同一流式请求跨峰谷边界默认不拆段。连续会话按时段拆分属于独立计费模式，只有实现了区间用量证据才能启用。

### RULE-05：服务等级及媒体规格

- 服务等级保存 requested/resolved 两份；不能把所有供应商的 `fast` 都映射成同一收费标准。
- 某节点不支持服务等级或费率未配置时，UI 明确提示，不自行虚构支持。
- 媒体条件采用允许列表：操作类型、尺寸/宽高、质量、分辨率、帧率（仅适用时）、是否含音轨、音频方向、生成数量。
- 模型选择固定规格，还是请求参数选择规格，需要适配器声明。
- 允许“按张价”和“图像 token 价”二选一，或按供应商规则组合；同一图像输出成本不得重复记账。
- 不支持/不认识的规格不能静默套最低价；返回未匹配原因，并遵循预算缺价策略。

## 8. 用量缺失、价格缺失与安全降级

### STATUS-01：外部可见状态

| 状态 | 意义 | 金额表现 |
| --- | --- | --- |
| `priced` | 所需数量与费率齐备，计算已完成 | 确定金额＋证据级别 |
| `estimated` | 使用了估算数量或参考价 | 估算金额＋原因 |
| `partial` | 部分组件可算、部分缺失 | 已知小计＋缺失项，不能当完整总额 |
| `unpriced` | 价格或汇率不足 | 未知，不是 0 |
| `missing_usage` | 缺少必要计量 | 未知或有明确标签的估算 |
| `pending` | 已预留，等待异步任务或最终 usage | 预留金额与最终金额分栏 |
| `free` | 明确免费或有证据表明没有上游成本 | 0＋明确原因 |
| `legacy_estimate` | 旧记录/兼容公式的估算 | 保留原值，不包装成新规则确认结果 |

### STATUS-02：对业务请求的影响

- 默认兼容策略：允许请求、记录诊断、展示未定价/估算状态，不因新增功能突然拒绝旧模型流量。
- 严格预算模式可显式选择“缺价拒绝”或“保守上界预留”；必须由管理员单独启用并展示影响。
- 缺价、规则冲突、缺 FX 必须有稳定错误码；不能变成不可解释的普通 500。
- 后台显示“计价覆盖率”和“本期未知成本请求数”，提醒用户报表不完整。

## 9. 请求、预算及异步结算

### FLOW-01：同步请求统一路径

1. 请求准入时取得不可变计价目录快照。在路由候选估价时调用公共引擎，传入该快照和完整请求上下文，不只传模型名。
2. 根据候选实际规则做预算预留；长上下文阈值依据单次尝试输入，不依据总重试预算倍数。
3. 尝试派发时从同一请求快照解析实际节点/模型价格版本，固定本次时间依据并记录估算依据。不同尝试可有不同合同价和派发时段，但不能混入请求开始后发布的新版本。
4. 流式/非流式解析归一化用量。
5. 生成唯一的 `CostComputation`，日志与预算共用该结果，不再分别重新读取“当前价格”。
6. 事务或可恢复 outbox 保证费用记录与预算应用的一致性；崩溃重放不能重复加预算或丢记录。
7. 将只读明细提供给日志、报表与后台，避免展示接口修改账务值。

### FLOW-02：预算精度与并发

- 已有全局、namespace、team、API key、workspace 作用域不得被削弱。
- SQLite 继续作为单实例路径；严格跨实例预算只在已支持的共享事务存储上承诺。
- 预留金额应有可解释的上界，缓存写入可能比普通输入贵，不能假设“全未命中必然最贵”。
- 严格模式下尽量在派发前控制上界；实际用量超过预留时仍需如实结算，不能为了不超预算丢弃成本或改写已返回响应。
- 预留/释放/提交均需幂等；过期预留回收不得误删仍在执行的异步任务。
- 修改预算成本口径必须显式批准；默认保持已部署行为。

### FLOW-03：本地缓存、失败和多次尝试

- 本地命中未调用上游时，本次上游费用是有明确原因的 0；缓存存储或查询的可选本地资源成本另算，不能混入供应商费用。
- 旧版本把命中返回的逻辑 token 计入预算，必须保留为兼容预算口径，直到管理员切换为“实际上游成本”口径。
- 一个客户请求可包含多个已计费的尝试；上游总成本应累加已知尝试费用，而不是只保留最后一次成功的价格。
- 失败 HTTP 状态不等于供应商未计费；若用量未知，保留未知标记。
- 只统计客户成功请求的内部分摊策略不得覆盖实际上游成本证据。

### FLOW-04：异步图片/视频任务

必需状态链为：`reserved → submitted → pending → terminal → settled`，另有显式失败/取消释放路径。

- 任务受理前固定价格版本、FX、规则上下文、预留数量；持久化后再依赖进程内记忆。
- 如果任务允许更换节点或重试，也持久化其计价目录快照引用；新出现、原快照未覆盖的节点不得静默套用最新费率，按缺价策略处理。
- 计量来源按供应商约定选择实际输出时长/数量；只能取得请求时长时，结果必须标记为估算或请求量计费。
- 完成、失败、取消、部分完成和投递失败分别处理。生成成功但下载失败可能仍有上游成本。
- 轮询、重复 webhook、服务恢复后重试、客户端重复提交通过幂等键与唯一约束去重。
- 终态结算只应用一次。以后得到更完整用量时写调整记录，不能静默覆盖原始结算。
- 任务中断后可恢复；在测试中模拟进程故障只允许针对隔离实例。

## 10. 版本、审计与历史可复算

### VERSION-01：生命周期

`draft → validated → scheduled/published → superseded/retired`。

- 草稿允许修改；发布版本只读。
- 请求准入快照包含当时有效的价格绑定、日历和 FX 引用；立即发布、定时生效和回滚都只影响此后准入的请求。请求内的重试/fallback 仍使用原快照，包括重试发生在版本生效边界之后的情况。
- 发布前校验版本、规则冲突、计量覆盖、币种、FX、权限及引用完整性。
- 修改使用 revision/ETag，拒绝覆盖他人刚发布的版本。
- 生效区间统一 `[effective_from, effective_to)`，不得重叠。未来生效版本可取消，已有费用引用的版本不可物理删除。
- 回滚是重新发布旧内容形成新激活记录，不修改旧版本，也不自动重算历史。
- 全局价格由默认管理域的管理员维护；workspace 管理员不能借调价影响其他工作区。
- 多实例发布需有一致的活动版本源；不能宣称每台机器各改 YAML 就能全局原子生效。
- 热路径使用内存中的编译只读价格簿，版本更新完整校验后原子替换，失败保留上一完整版本。

### VERSION-02：明细和历史

每笔新记录至少能回查：请求/尝试/任务 ID、规则/版本哈希、规范用量、数量来源、单价组件、计价时间、FX、取整与调整项、最终状态。

- 历史展示以记录的计算快照为准，不按现价覆盖原费用。
- “按新规则回放”只生成独立模拟结果，与原记录并排显示。
- 旧记录没有足够用量证据时标记 `legacy_estimate` 或 `not_replayable`；不能编造缓存 TTL 或视频秒数。
- 价格版本保留期不得短于引用它的费用记录。日志清理和价格清理相互约束。
- 明细只保存计价元数据；可复算不要求保存 prompt 或媒体文件。

## 11. 后端模块与接口设计

### ARCH-01：模块职责

| 模块 | 职责 | 禁止事项 |
| --- | --- | --- |
| Usage Normalizer | 协议用量转统一数量/来源 | 不访问价格数据库，不存原始内容 |
| Pricing Rule Compiler | 校验、归一化、冲突检测、构建只读索引 | 不在请求中抓取官方网页 |
| Price Resolver | 按上下文返回固定规则及选择解释 | 不静默补虚构价 |
| Cost Calculator | 纯函数精确计算，供真实结算与试算共用 | 不写数据库、不发网络请求 |
| Pricing Repository | 草稿、版本、绑定、来源、发布事务 | 不依赖专有中转站服务 |
| Cost Settlement | 预留、最终快照、幂等/调整、预算接入 | 不混淆销售收费与上游成本 |
| Pricing Dashboard API | 权限、脱敏、校验、变更审计 | 不返回真实供应商凭证 |
| Compatibility Adapter | 旧价格字段投影/无损导入 | 不静默改变旧预算语义 |

### API-01：拟定接口契约

路径可在 M0 与现有路由统一，但必须保留以下操作和权限语义：

| 方法/路径 | 功能 | 权限/安全要求 |
| --- | --- | --- |
| `GET /api/dashboard/pricing/books` | 价格簿摘要与覆盖状态 | 按管理作用域过滤 |
| `GET /api/dashboard/pricing/books/:id` | 有效规则、继承来源与版本 | 无密钥/原始响应 |
| `POST /api/dashboard/pricing/books` | 创建价格簿与首个草稿 | 管理员，审计 |
| `POST /api/dashboard/pricing/books/:id/drafts` | 从指定版本派生草稿 | 版本引用，不覆盖发布态 |
| `PUT /api/dashboard/pricing/drafts/:id` | 更新草稿 | revision/ETag，拒绝丢失字段 |
| `POST /api/dashboard/pricing/drafts/:id/validate` | 冲突、单位、缺价校验 | 只读检查，不生效 |
| `POST /api/dashboard/pricing/quote` | 单次人工用量试算 | 不调用真实模型，不修改预算 |
| `POST /api/dashboard/pricing/replay` | 小批量已授权元数据回放 | 有行数/时间上限，不改历史 |
| `POST /api/dashboard/pricing/drafts/:id/publish` | 立即/定时发布 | 管理员、原因、确认、原子事务 |
| `POST /api/dashboard/pricing/books/:id/rollback` | 重新激活旧内容的新版本 | 管理员、原因、影响预览 |
| `POST /api/dashboard/pricing/import/validate` | 校验导入/旧配置转换 | dry-run 默认，不接受可执行内容 |
| `GET /api/dashboard/pricing/books/:id/export` | 导出完整可移植规则 | 去除机器路径、凭证及私有注释 |
| `GET /api/dashboard/logs/:id/cost-breakdown` | 请求费用明细 | 必须按请求所属 workspace 鉴权 |

所有变更接口检查实际资源作用域，不能只信任客户端提交的 workspace ID。副作用接口沿用认证、CSRF/会话安全与请求体限制；不能以 GET 执行发布。

错误码至少包括：`pricing_rule_conflict`、`pricing_unit_mismatch`、`pricing_version_conflict`、`pricing_dimension_missing`、`pricing_fx_missing`、`pricing_calendar_unavailable`、`pricing_unknown_variant`、`unsupported_rule_mode`、`pricing_permission_denied`。

## 12. 前端配置方案

### UI-01：入口与信息架构

- 新增价格管理入口，可从供应商 → 模型 → 计价配置进入同一个编辑器。
- 保留节点向导中的简洁价格摘要和基础编辑，不把所有高级表单塞进节点向导。
- 模型列表展示当前模式、币种、价格来源、版本、覆盖/继承、待审核、缺价及定时生效状态。
- 成本页面展示计价覆盖率和未知金额数量，不给不完整统计贴“精确成本”标签。

### UI-02：编辑器六个区域

| 区域 | 配置与交互 |
| --- | --- |
| 基础与缓存 | 普通输入、输出、缓存读、写入 TTL；币种、单位、来源；区分免费、继承、未配置 |
| 上下文阶梯 | 可视行表编辑范围、整单/分段模式、各维度价格；自动显示边界和冲突 |
| 时间与服务等级 | 时区、星期、多时间窗、节假日/日期覆盖、Standard/Priority/Flex/Batch 变体 |
| 多模态 | 按能力显示次数、图片数、音频/视频时长、字符、细分 token、规格矩阵、取整和最小单位 |
| 试算与影响 | 输入合成用量、时间、等级、规格；显示命中规则、公式、缺失项、原币/报告币；可比较草稿与发布价 |
| 版本与发布 | 修改原因、生效时间、审计记录、参考来源、差异预览、发布确认、回滚 |

### UI-03：表单行为约束

- 纯文本模型不默认展示视频规格；纯图片模型不强制填无意义的输入/输出 token 单价。
- “空白”“继承”“显式 0 元”必须是三个可区分状态。不能用 `Number('') === 0` 把空白变成免费。
- 未修改或不可见字段必须原样保留，编辑无关节点字段不得覆盖高级价格或模型能力。
- 单价及金额用字符串状态，输入单位和换算后的显示单位明确。
- 规则保存前提供确定性校验；发布前必须展示所有警告及受影响绑定。
- 如果选择峰谷规则却没有有效日历，或选择价格维度但没有用量适配器，阻止“已完整配置”误导。
- 删除/回滚/发布有二次确认；普通草稿保存不改变活动价格。
- 有权限错误、网络错误、冲突、加载、空状态、未保存提示和键盘可达控件。
- 编辑草稿遇到版本冲突后重新载入/比较，不自动覆盖。
- 无真实外部发送的试算接口可在隔离 UI 中完整验证。

### UI-04：请求明细和报表

请求费用详情必须显示：原始规范用量与计费数量、每维度单价、命中规则、版本、时段、服务等级、媒体规格、汇率、取整、已知小计/最终总额、计价状态及差异原因。

本地缓存展示“本次上游成本”“逻辑使用量/预算口径”“参考节省”三个分离值。异步视频展示预留与最终结算，不在任务刚受理时显示为已确认费用。

### UI-05：国际化与适配

- 全部新文案覆盖 `en`、`zh`、`zh-TW`、`ja`、`ko`、`th`、`es`，沿用现有视觉系统。
- 数字、日期、时区、币种格式随界面 locale，计算不依赖格式化字符串。
- 必须在桌面、窄屏、暗色及至少中英文状态下做真实浏览器检查。
- 表格窄屏可局部滚动或折叠为字段组，但整页不得横向溢出；隐藏列不能让未显示配置被丢弃。

## 13. 迁移与兼容策略

### MIG-01：向后兼容

1. 保留旧 `models_pricing`、节点 `model_capabilities.pricing` 输入，通过版本化兼容适配器读取。
2. 旧四类 token 配置在兼容模式下得到与原始实现等价的预算/展示结果，精度差异要有测试和解释。
3. 旧目录中的媒体字段迁移时只生成草稿或受标记估算，不因字段存在就宣称数量已被采集。
4. 新配置不反向强制写回旧 schema；新旧优先级必须明确，避免同一个模型同时双份生效。
5. 保留价格来源/可信度字段，避免破坏现有目录、缓存收益、成本异常和路由推荐页面。
6. 旧历史行保留原始金额；新状态与新增明细使用加法迁移，不破坏原字段。
7. API keys、Dashboard 认证、协议转换、流式工具事件、provider 配置和 SDK 必须保持回归通过。

### MIG-02：数据库变更

- 使用显式、可检查的迁移；不得依赖启动时 `synchronize` 在生产自动改表。
- SQLite 与 PostgreSQL 分别提供 dry-run、迁移和恢复演练。
- 大表优先新增旁路费用明细表及必要索引，评估锁时间和磁盘预算，不在首次启动自动逐行全量回填。
- 价格和结算数据必须保留 workspace、请求及任务关联；系统价格资源的全局作用域须有独立权限控制。
- 新旧应用并存与回滚兼容性必须说明；如果不能降级，最终报告必须明确写出前置数据恢复要求。
- 生产迁移只在后续单独批准的部署窗口执行，本 Goal 开发阶段不运行。

### MIG-03：选择启用新引擎

迁移完成不代表立即切换所有模型。需要按绑定范围选择新引擎，先用合成/脱敏样本对照，再显式激活。

管理员尚未确认的价格、峰谷日历、FX、预算口径不得自动转为新默认。功能上线后日常调价不应需要重启；首次引入代码和数据库结构仍按受控发布流程执行。

## 16. 性能、资源和容量验收

### PERF-01：热路径要求

- 价格核心纯内存计算，不在每次模型请求中进行价格网页、汇率、节假日网络查询。
- 编译后的索引应避免扫描全部模型价格；只匹配目标模型/节点的规则候选。
- 应有发布态规则数和试算请求体的可配置上限。超出上限返回校验错误，不拖垮服务。
- 报表或回放分页执行，不在请求中加载整张生产日志表。

### PERF-02：可重复对比方法

在隔离机器/进程中生成至少 1000 个模型绑定、每绑定 20 个规则、每规则 12 个组件的合成数据。

- 使用固定 runtime、数据集、预热和随机种子，记录 10000 次 quote 的 p50/p95/p99。
- 目标：无网络纯 quote 的 p95 不高于 2ms，p99 不高于 10ms；记录机器规格，不对所有客户机器承诺同值。
- 与旧版本跑相同 mock-upstream 场景，目标新增 Gateway p95 开销不高于 5ms、吞吐下降不高于 5%。
- 测试资源受第 0 节约束；本机生产压力不允许时，应转到独立环境或明确列为待验证，而不是照跑。
- 超出目标要提交 profile 和原因；未经用户接受不能写成“性能通过”。

这些是验收目标，不是当前已测得性能。SQLite/PostgreSQL 写入开销与纯函数开销要分别报告。

| 部署模板 | `npm run validate:k8s`，实际 Docker 镜像 smoke；systemd 模板按目标平台验证 |
| 数据库 | 隔离 SQLite 与临时 PostgreSQL 的迁移、并发/唯一约束、恢复测试 |
| SDK | 修改 SDK 类型时执行 TypeScript/Python SDK 对应测试；未改也保留兼容检查 |
| 性能 | PERF-02 的合成数据 microbenchmark 与固定 mock-upstream 对比 |

不得因缺少 Docker/PostgreSQL 而把跳过写作通过。可以继续其他隔离工作，但完整发布就绪状态需要补齐证据，或由用户显式接受具体的未验证风险。

## 20. Definition of Done 与停止规则

### DONE-01：规格阶段完成

- 本文完整覆盖目标、差距、后端、前端、迁移、验收和运行安全。
- 文档通过链接与内容检查；没有实现代码或生产修改。
- 向用户交付路径，明确实施仍待确认。

### DONE-02：未来开发阶段完成

- SCOPE-01 中所有必需能力与对应 UI/API 完成，支持范围写清，未支持模式不可启用。
- CALC、STATE、UI、MIG、OPS 测试均有可复核结果；失败没有被隐藏为跳过。
- 旧业务回归、精度、权限、版本固定、幂等与恢复验证通过。
- 性能结果满足目标，或用户明确接受有量化证据的偏差。
- 已固定源码提交和候选哈希；不在发版清单上用一个旧版本号掩盖新代码身份。
- 没有未经授权的生产变化；所有测试实例停止或在交付中明确说明。
- 完整候选包与部署/回滚清单已交付。
- 明确输出：**`READY_FOR_REVIEW_NOT_DEPLOYED`，生产 2099 未由本任务重启。**

### STOP-01：仍然必须等待用户的事项

即使 DONE-02 全部满足，也不得执行部署。应列出下列待确认项后停止：

1. 哪一个候选提交/版本获准部署。
2. 维护窗口、允许的短暂中断、在途请求处理方式。
3. 是否运行该版本数据库迁移，以及备份与回滚策略。
4. 哪些模型/节点首次启用新引擎，采用什么已批准费率、日历、FX 和预算口径。
5. 是否推送/合并/发布 GitHub；代码发布与运行部署分开说明。

此前对可靠性或告警功能的部署批准不涵盖本计价改造。

## 21. 后续获准部署时的独立流程

本节仅定义将来的操作契约，不授予现在执行权限。

1. 重新核对生产 PID、活动发布、配置校验和、数据库类型、磁盘空间与候选来源；不能复用开发开始时的过期判断。
2. 确认用户批准的版本/窗口。已有长请求、长连接不等于可安全中断；受限并发计数为 0 也不能单独证明无活跃请求。
3. 在窗口内制作 WAL 安全 SQLite 备份或 PostgreSQL 一致性备份，验证可读取/恢复；不使用裸 `cp` 复制活库。
4. 只有在本次批准中获准，才暂停看门狗并进入维护；避免由自动恢复与人工发布互相干扰。
5. 按已演练的迁移计划执行必要数据变更，保留旧发布目录和恢复材料。
6. 原子切换候选，执行一次计划内 Gateway 重启，验证 `/live`、`/ready`、认证、模型请求、试算、价格版本、预算和日志明细。
7. 验收失败时按预演路径回滚。应用降级不能自动撤销新增结算或数据变更，需按兼容策略处理。
8. 恢复看门狗，观察自动探测和错误率；记录实际停机时间、新 PID、运行清单和部署结果。
9. 后续日常调价走价格版本发布，不再因改价重启服务。

## 22. 必须在实施前确认的业务口径

为避免开发过程中反复询问，下列默认值可用于合成测试与草稿。生产激活前仍需管理员确认，不自动应用到现网。

| 决策 | 隔离开发默认 | 生产边界 |
| --- | --- | --- |
| 预算口径 | 保持 legacy 兼容，另展示真实上游成本 | 改为新口径需明确批准 |
| 长上下文 | 整单阶梯，边界可配置 | 不按模型名前缀自动套所有 GPT |
| 峰谷时间依据 | 每次尝试派发时间 | 如合同按接收/完成时间计价需明确设置并验证 |
| 价格来源 | 管理员确认的节点/模型价优先 | 厂商官网是参考，不覆盖合同价 |
| 无价格 | 请求兼容放行、明确未知成本 | 严格拒绝/上界预留必须显式启用 |
| FX | 合成固定比率，仅用于测试 | 原币/报告币与正式 FX 来源由管理员设置 |
| 媒体时长 | 保存精确数量，按规则取整 | 按实际还是按请求，按合同与可取得证据配置 |
| 草稿发布 | 隔离环境可立即生效 | 生产首次引擎/迁移必须经过部署批准 |
| 历史 | 原费用不变，新规则模拟另列 | 不自动全量重算、回填或删除 |
| 官方价模板 | 带版本/来源的合成或已核验草稿 | 实施时重新查证，不能使用过期记忆硬编码 |
