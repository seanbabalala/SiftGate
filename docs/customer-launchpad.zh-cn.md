# Launchpad：从激活到第一次调用

开发分支功能，尚未发布。不会升级或重启任何正在运行的网关。

## 客户看到的四步

1. **确认环境**：读取当前工作空间、服务器实际时区、下次日周期边界。页面不会改服务器时钟；时区变更仍须运维维护窗口。
2. **接入模型**：复用现有供应商连接编辑器。先填写凭据，再明确启用样例节点，选择一个文本模型。配置成功不等于连通性成功。
3. **创建受限 Key**：固定为单节点、单模型、`chat_completions`、`text`，关闭 auto 路由，仅允许直连；必须填写正的日 Token/美元额度与 RPM。也可选用完全满足该约束的现有 Key。
4. **验证真实调用**：核对价格和时区，确认已保存 Key，再单独确认一次可能计费的请求。请求经过真正的 `/v1/chat/completions` 和 API Key 认证，不借用管理后台权限绕过调用认证。固定短提示词、16 Token 输出上限；不自动重试。

示例额度不是供应商账单保证，16 Token 请求参数也不是供应商计量保证。模型不支持该请求形态时，使用高级 Playground/客户端按相应协议配置，不伪造成功。

## 什么才叫“验证通过”

- 后台先保存一条五分钟有效的测试意图，包含工作空间、选中 Key ID、节点、模型、配置/权限摘要与费用确认。
- 发送前比较用户粘贴的 Key 和所选工作空间 Key；不匹配时不发送模型请求。
- 浏览器只发送一次真实请求，关联 `x-session-key`。准备操作和回执查询均不调用供应商。
- 回执必须找到该工作空间、该 Key、该关联 ID 的实际调用记录，且在意图有效窗口内；HTTP 成功、无错误、节点和模型一致后才显示通过。
- “待记录”“未知”“失败”“配置已变更”和“已验证”分别显示。网络中断时，服务器可能仍在执行；不自动重发。
- 当前配置、Key 权限、额度、轮换前缀或时区变化会使旧证据变为过期设置，要求重新核对。日常 last-used 更新时间不导致证据失效。
- 浏览器刷新会从持久的审计/调用记录重建状态，而不是信任 localStorage 的绿色勾。记录被清理、工作空间/Key删除或证据不可读取时不再宣称成功。
- 它证明过去一次请求可用，不是持续健康监控，也不是发布/升级可回退的证明。

## 权限与秘密

- Launchpad 写操作仅供当前工作空间管理员；只读观察和证据遵循工作空间访问权限。
- 新 Key 的权限在服务端固定，不接受请求体把 `allow_auto` 打开或清空白名单来扩大权限。
- 新 Key 仅返回一次，页面内存中展示；不放入查询缓存、URL、localStorage、上手回执或普通日志。复制需要客户主动点击，代码示例只使用 `$SIFTGATE_API_KEY` 占位引用。
- 创建响应断开时先查看 Key 中心，避免再次点击生成重复 Key。唯一名称与事务化审计保护现有创建流程。
- 选择偏好按工作空间保存，仅包含节点、模型和 Key ID，不保存凭据或“完成”标记。
- 未保存新 Key / 操作进行中有离开提醒；工作空间切换被阻止；旧页面异步结果不写入新页面。
- 准备阶段会通过已有 Key 服务校验密钥，这可能更新该 Key 的 last-used 元数据；并不代表发生了供应商调用。

## 新的显式节点开关与旧版兼容

旧安装器曾输出 `enabled: false`，但该字段在节点运行时没有对应开关。不能在升级时突然赋予它“禁用流量”的新含义，否则旧客户保存过供应商凭据后仍残留的字段会造成停服。

本分支使用新的 **`nodes[].disabled: true`**：

- 新安装器的样例节点设置 `disabled: true`，阻止新上游 HTTP/媒体/实时连接及主动健康探测。
- 启用时显式提交 `disabled: false`；现有配置没有该字段时维持原行为。
- 老的、曾被忽略的 `enabled: false` 不被自动转义、不被批量迁移。因此升级现有安装不会因为该旧字段突然断流。
- 不会取消已经发出的请求；显式禁用也会阻止后续供应商轮询等新请求，操作前应考虑未完成任务。
- 新开关独立于熔断器，不能因为关闭熔断就绕过运维禁用。

## API 摘要

| 路径 | 权限 | 效果 |
|---|---|---|
| `GET /api/dashboard/launchpad` | 工作空间读权限 | 实际时区、节点、匹配受限 Key、配置摘要、最近对应意图 |
| `POST /api/dashboard/launchpad/keys` | 管理员 | 核对配置摘要后创建受限 Key，与审计在同一事务中 |
| `POST /api/dashboard/launchpad/prepare-test` | 管理员 | 核对 Key、费用确认、时区与配置；保存意图，不调用模型 |
| `GET /api/dashboard/launchpad/attempts/:id` | 工作空间读权限 | 根据审计意图和调用记录重建回执，不重发请求 |

配置摘要用于检测变化，不是发行签名或供应商状态证明。外部动态密钥后端的值变化、未改变配置文件的供应商行为变化，不被摘要当作可用性保证。

## 本轮边界

- 先闭合单个文本模型的首次调用。图片、视频、实时等复杂接入仍在原高级页面。
- 不增加云账号、不建立中心依赖、不挂 Docker socket、不发送真实付费测试请求进行开发验收。
- P1 的独立 Operator、升级中心、备份验证中心；P2 的审批、批次与离线发布，不因本页存在而宣称已交付。
- 最终镜像发布、跨版本演练、旧实例迁移和现网2099升级均需独立门禁与授权。
