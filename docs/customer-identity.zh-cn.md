# 本地管理员身份：激活、恢复与运行边界

**未发布的 P0-A 功能，2026-10-08。** 新身份模式必须使用配套的新镜像与安装工具。
v2.11.7 客户仍以原安装包文档为准。本文不授权升级任何运行中的实例。

## 三类秘密，各司其职

| 凭据 | 用途 | 生命周期 |
|---|---|---|
| 激活码/恢复码 | 证明安装操作者授权设置管理员凭据 | 256位随机值，15分钟单次使用；重签使前一码无效 |
| 管理员密码 | 登录本地控制台 | 用户设置；仅保存 bcrypt 哈希，不发送邮件、不写普通日志 |
| Gateway API Key | 调用模型 API | 独立管理；修改管理员密码不会修改它 |

浏览器需 HTTPS，除受信任的本机 loopback 测试。HTTPS 代理须正确透传原始 `Host`，
不能把任意 `Forwarded` 头当作可信的来源。界面只显示浏览器当前实例地址，不宣称
知道用户密码属于哪台机器。

## 状态与端点

- 新安装器创建本地 `/config/dashboard-identity.json`，写入待认领状态和激活码哈希。
- `GET /api/auth/status` 返回 `identity.mode/setupRequired/activationExpired`，禁止缓存。
- `POST /api/auth/identity/activate`：`code` + `password`，成功后另行登录。
- `POST /api/auth/identity/recover`：`code` + `password`，撤销旧控制台会话。
- `POST /api/auth/identity/password`：管理员会话 + `current_password` + `password`。
- `access-code --purpose activate|recover --confirm` 仅是主机工具命令，不提供对应 HTTP 发码接口。
- 非 managed 模式不开放上述身份操作；原登录和 OIDC 路径保留。

写操作有跨源检查，和登录共用尝试次数限制。密码不少于15个Unicode字符、至多72个
UTF-8字节，不含NUL；允许粘贴、密码管理器和空格口令。暂不包含泄露密码库检查、
本地MFA、独立多人身份、OIDC混用、账号邮件验证或强制企业密码策略，不应超范围宣传。

## 文件安全与故障

身份及码文件为 0600，目录不可由其他账户写入。身份读取拒绝符号链接、非普通文件、
超大文件和不安全权限。并发写入用排他锁、revision重查、临时文件、fsync及原子rename。
只支持本机单实例文件系统；不是共享网络盘/分布式锁方案。

一个码文件和一个身份文件不是跨文件事务：断电可能留下已过期或未提交的码文件，
以身份文件中的哈希和期限为准。签发失败不能直接使用看到的新码；诊断后重新签发。
rename之后目录fsync若失败，调用可能返回失败但状态已经变更；先重新检查当前状态、
尝试新密码或重新签发恢复码，不覆盖数据库或重新运行 `init`。

进程被杀死可能遗留 `dashboard-identity.json.lock`。**不要自动或按时间盲删锁**。
由主机管理员确认没有安装器/凭据写操作在执行，保存现场，检查身份文件、权限和
本地磁盘。不能证明锁已失主时，安排该测试/客户实例的维护窗口后再处理锁；不要
因此重启其他服务或现网2099。读到缺失/损坏身份时不会新建管理员入口。

身份文件丢失无法从登录网页恢复；需要合法备份及主机管理权限，或专门的受控迁移
流程。普通配置回滚不回滚独立身份文件。手工复制旧身份文件可能复活旧会话，因此
必须使用配套的独立恢复流程，不能自行拷回签名密钥。

## 兼容性与发布

新模式是单个本地 `dashboard` 管理员，不能冒充按人审计；`last_action/changed_at`
只是本地最新状态元数据，不是完整不可篡改审计日志。企业身份与完整操作审计在后续阶段。

旧身份配置不自动迁移。旧版密码加独立 `session_secret` 的安装，单改密码并不撤销
旧JWT；继续使用其原流程，不能套用新身份模式的撤销承诺。源代码直接启动无凭据
改为拒绝启动；维护者必须在正式发版说明标注此变化。

发布新功能前需验证安装包/镜像组合，跑安装和备份恢复验收；需要实际跨版本升级
证据，而不只是同代码不同digest镜像替换。参见 [实施范围](customer-lifecycle-goal.zh-cn.md)
与 [客户运维命令](customer-install.zh-cn.md)。
